# LifeDots Android UX review — 2026-10-25

## Implemented decisions

- The saved calendar is the primary content on home and in Customize. Both use the shared wallpaper renderer, explicitly selecting the saved Yil/Umr mode. Auto-switch is disabled only in a preview copy; the saved rotation preference remains intact. Preview uses the current display's aspect ratio, renders off the UI thread, coalesces rapid slider edits, and refreshes on resume and each minute while visible. It is labeled as a still image.
- Home scrolls, respects Android system insets, retains status/navigation bars, and lets action labels wrap. Brand artwork remains decorative behind the functional preview. Applying a static wallpaper shows a working state, performs the operation off the UI thread, and reports success or the controller's error. Resume refresh delegates to the ownership-aware controller.
- Entering Customize no longer changes the saved view mode or month labels. Calendar/monthly/continuous modes are explicit choices. Calendar supports 2, 3, or 4 columns, month labels, and Monday/Sunday week starts.
- Material switches and sliders provide Android accessibility semantics and touch targets. The reusable interval slider refreshes when its saved value changes, detects fast and reverse tick crossings, and includes remaining seconds in fractional-minute labels. Mode/theme/layout/person choices expose selected state. Replacing raw gesture handlers also prevents callbacks from retaining the previously selected Yil/Umr mode when editing position or opacity.
- Static lock-screen mode explains that daily image refresh and automatic live rotation differ. Auto-switch controls are hidden in this mode without clearing the stored preference.
- A signing mismatch offers an explanation and keeps the current app. The UI no longer offers self-uninstall, which would destroy saved data and its privately cached downloaded update. Opening home no longer deletes downloaded updates.
- Android's native date picker replaces the custom picker that could save March after selecting February 31. Birthday entry validates real dates, four-digit years, and dates no later than today. Birthday edits stay in a rotation-preserved draft until Done; dismissal cancels edits. Empty fields remove that person's birthday explicitly. Numeric fields expose Day/Month/Year labels and keyboard Next/Done actions.
- Goal/event drafts survive rotation and deletion requires confirmation. Editors remain scrollable; the title input and action buttons can grow for larger text.

## Evidence and remaining verification

- `IntervalSliderMathTest` adds fast/reverse crossing and fractional-minute label regressions.
- `BirthdayDraftTest` covers impossible February dates, leap years, partial years, future birthdays, and optional empty versus incomplete input.
- Static diff review passed `git diff --check` before integration.
- Build, shared-renderer comparison tests, and device checks are coordinated by the root integrator; this note does not claim those have passed.
- Device verification should cover home and settings screenshots; actual saved calendar versus preview; Yil/Umr selection followed by per-mode slider changes; 2/3/4-column calendars; birthday Done versus dismissal; keyboard/large-font/landscape overflow; and update mismatch explanation. Setting wallpapers, changing device permissions, and uninstalling are separate operations requiring the user's authorized scope.
